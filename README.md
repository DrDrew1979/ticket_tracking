# ✈️ flight-monitor

Слежение за ценами авиабилетов 24/7 на GitHub Actions **+ Telegram-бот
для семейно-дружеского круга**: каждый пользователь настраивает своё
отслеживание прямо в чате — **7 укрупнённых шагов с кнопками**
(календарь, «цифровые часы», предвыборы и умолчания, любые параметры
можно оставить как есть), бот присылает мгновенные пуши о падении цены
и персональные дайджесты, а при запуске отслеживания — короткую шутку
про маршрут. Сервер не нужен. Стоимость: 0 ₽.

## Как это устроено

- **Постоянно, сменами по ~5,5 часов** workflow `tg-live-poll`
  держит **непрерывный long polling** Telegram: ответ на сообщение —
  **1–3 секунды**, весь визард проходится за минуту-другую.
  Запросов к API цен нет — только команды. Единственная пауза —
  ~1–2 минуты старта нового раннера раз в ~5,5 часов (апдейты за это
  время Telegram хранит и отдаёт сразу после старта; ничего не теряется).
- **Каждые 30 минут** workflow `flight-monitor` в режиме `monitor`:
  опрашивает кэш цен Aviasales (Travelpayouts Data API) по трекингам
  и коммитит базу `prices.db` обратно в репозиторий (команды бота в
  этот момент забирает `tg-live-poll`, чтобы не конфликтовать с ним).
- **Частота опроса**: админ — каждый прогон (*/30 мин), остальные
  пользователи — **не чаще раза в час**, с общим бюджетом
  `pairs_budget_per_run` пар за прогон (защита от перегрузки).
  Свой трекинг админ настраивает точно так же, как все — командой
  `/watch` (его слот не занимает лимит `max_active`).
- **Алерты**: цена пары ≤ цели пользователя **и** ≤ минимума за 30 дней
  наблюдений → мгновенный пуш с deeplink на Aviasales (дедуп 12 ч).
- **Персональные дайджесты** (ежечасный cron): текущие цены, тренд
  «ждать/брать», отсечка, советы по целевой цене — по расписанию
  пользователя (1/3/7/14 дней, своё время по МСК).
- **Авто-очистка**: как только даты трекинга прошли, пользователь
  удаляется из базы (может вернуться через /start); наблюдения старше
  45 дней стираются (retention), база не растёт бесконечно.
- Покупка **вручную** по ссылке из пуша (3-D Secure не позволяет иначе).

## Мультипользовательский режим

- Один пользователь = **одно активное отслеживание** (направление, даты,
  цена). Лимит активных трекингов обычных пользователей: `max_active: 39`
  (слот администратора — всегда вне лимита).
- Новые пользователи регистрируются свободно; если лимит исчерпан —
  попадают в **лист ожидания** (параметры сохраняются, бот сообщит о
  освободившемся месте, активация по /retry).
- **Персональные данные зашифрованы** (репозиторий может быть публичным):
  chat_id, имена, параметры трекинга и черновики диалогов лежат в базе
  только в виде Fernet-шифротекста. Ключ — в секрете `DB_KEY`. Поиск по
  пользователям — по необратимому HMAC(chat_id). Утечка репо не раскрывает
  ни личностей, ни планов поездок.
- **Бан** (тихий режим): забаненный не получает никаких ответов.
  Мягкое удаление: пользователь может вернуться через /start.

### Команды пользователя

Кнопка «Меню» (рядом с полем ввода, setMyCommands) и команда `/menu`
показывают все команды кнопками.

| Команда | Действие |
|---|---|
| `/start` | регистрация; новичку — сразу мастер настройки |
| `/watch` | настройка отслеживания (7 укрупнённых шагов, кнопки) |
| `/edit` | изменить отслеживание по всем параметрам (прежние значения подставлены) |
| `/menu` | меню команд кнопками |
| `/status` | сводка текущего отслеживания |
| `/stop` | удалить отслеживание (кнопки да/нет) |
| `/retry` | активировать сохранённые параметры, когда появилось место |
| `/cancel` | прервать настройку |
| `/help` | справка (админу — с админ-секцией) |

Шаги визарда (все выборы — кнопки; после каждого принятого значения —
подтверждение «✅ Принято: …»; сообщение редактируется на месте):
1. **Город вылета** — ввод названия с поиском по опечаткам → выбор
   варианта кнопкой (город «все аэропорты» или конкретный аэропорт).
2. **Город прилёта** — так же.
3. **Тип поездки** — кнопки «только туда» / «туда и обратно» (для
   «только туда» шаг 5 пропускается, нумерация 6/6).
4. **Окно вылета** — дата в календаре (листание месяцев и годов,
   Пн — первый день недели, суббота/воскресенье и праздники
   производственного календаря РФ помечены 🔴) → длительность 1–4
   дня → время: по умолчанию весь день (00:00–23:59), опционально
   «Настроить время суток» — цифровые часы с кнопками (можно и
   текстом «1057» = 10:57).
5. **Окно возврата** (только туда-обратно) — не раньше окончания
   окна вылета; подменю времени аналогично.
6. **Отсечка и целевая цена** — отсечка по умолчанию за 14 дней до
   начала окна вылета (но не раньше сегодняшнего дня), можно выбрать
   другую дату в календаре; пока бот ищет цену, показывает
   «⏳ Секундочку, вычисляю текущий уровень цен…», затем одним
   запросом к кэшу Aviasales предлагает целевую цену на 15% ниже
   минимума (кнопка) — либо своя цена, либо «без цели».
7. **Дайджест** — частота кнопками (по умолчанию 1 день) и время
   (по умолчанию 09:00 МСК) → «Подтвердить».

Финальное меню — сводка с кнопками «✅ Подтвердить» и «✏️ Изменить»
(правка любого блока с возвратом к проверке). /edit подставляет
прежние значения: каждый блок можно оставить кнопкой «⏭ Оставить».
При подтверждении бот присылает шутку (до 250 знаков) про маршрут
и сезон поездки. Шутку генерирует LLM Z.ai (бесплатная Flash-модель,
персонально под комбинацию «город вылета → город прилёта + время
года»). Секрета `ZAI_API_KEY` нет, модель не ответила за 5 секунд или
ошиблась — подтверждение просто уходит без шутки, без каких-либо
сообщений об ошибках.

Производственный календарь РФ (data/holidays.json) обновляется
workflow `holidays-update` раз в ~90 дней из открытого API
isdayoff.ru; при недоступности используется встроенный фолбэк
(фиксированные праздничные даты без переносов).

### Админ-панель (в личном чате владельца)

`/users` — интерактивная панель: под каждым пользователем кнопки
«ℹ️ инфо» (карточка), «🗑» (удаление с подтверждением) и
«🚫 бан» / «✅ разбан». Команды тоже работают:

| Команда | Действие |
|---|---|
| `/stats` | пользователи, активные трекинги, лист ожидания |
| `/users` | панель пользователей с кнопками |
| `/user N` | карточка: chat_id, имя, дата входа, параметры трекинга |
| `/del N` | мягкое удаление (можно вернуться через /start) |
| `/ban N` / `/unban N` | бан (тихий режим) / разбан |

## Установка

1. **Репозиторий** на GitHub (приватный — до ~8 пользователей; для
   большего круга переведите в **Public** — минуты Actions станут
   бесплатными безлимитно, а персональные данные уже зашифрованы).
2. Загрузите файлы проекта (`Add file → Upload files`).
3. **Travelpayouts**: токен с [travelpayouts.com](https://www.travelpayouts.com).
4. **Telegram-бот** у @BotFather → токен; ваш chat_id у @userinfobot.
5. **Секреты** (Settings → Secrets and variables → Actions):

   | Секрет | Значение |
   |---|---|
   | `TP_TOKEN` | токен Travelpayouts |
   | `TG_TOKEN` | токен бота |
   | `TG_CHAT_ID` | (опционально) ваш chat_id — запасной адресат админских сообщений, если не задан `ADMIN_CHAT_ID` |
   | `DB_KEY` | ключ шифрования: `python -c "from src.crypto import gen_key; print(gen_key())"` |
   | `ADMIN_CHAT_ID` | ваш chat_id (админ; = TG_CHAT_ID) |
   | `HC_URL` | (опционально) ping-URL healthchecks.io |
   | `ZAI_API_KEY` | (опционально) API-ключ Z.ai для LLM-шутки к подтверждению; ключ — z.ai → API → [API Keys](https://z.ai/manage-apikey/apikey-list) → Create API Key. Модель по умолчанию `glm-4.5-flash` (бесплатна); без секрета шутки отключаются автоматически |

6. Включите Actions, проверьте вручную: Run workflow → mode=`monitor`.
   В логе: «Пользователи: опрошено…». Напишите боту `/start` и настройте
   трекинг — ответы приходят за 1–3 секунды (workflow `tg-live-poll`
   должен быть включён, см. «Частые проблемы»).

## Частые проблемы

- **`ValueError: Fernet key must be 32 url-safe base64-encoded bytes`** —
  секрет `DB_KEY` задан, но это не Fernet-ключ (его нельзя придумать
  самому или взять из пароль-менеджера). Варианты генерации:
  - на компьютере с Python:
    `python -c "import base64, os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"`
  - **без Python** — в консоли браузера (F12 → Console), одной строкой:
    `(() => { const k = btoa(String.fromCharCode(...crypto.getRandomValues(new Uint8Array(32)))).replace(/\+/g,'-').replace(/\//g,'_'); console.log(k); try { copy(k) } catch(e) {}; return k; })()`
    — ключ появится в консоли и попадёт в буфер обмена.
  Вставьте результат (44 символа, заканчиваются на `=`) в секрет `DB_KEY`.
  ⚠️ Ключ — секрет: не отправляйте его в чаты и не коммитьте в репозиторий.
  Без ключа бот не принимает команды пользователей и не следит за ценами;
  админу приходит разовое оповещение о проблеме.
- **Бот не отвечает на /start** — проверьте секреты `TG_TOKEN`, `DB_KEY`
  и `ADMIN_CHAT_ID` (или `TG_CHAT_ID`): без `DB_KEY` приём команд
  отключён. Также убедитесь, что workflow **tg-live-poll** включён
  (Actions → tg-live-poll → ⋯ → Enable workflow) и его запуски зелёные.
- **`no such column: uid`** — устранено в текущей версии `src/db.py`;
  убедитесь, что файл в репозитории совпадает с версией из архива
  проекта (миграция выполняется до создания схемы).
- **Бот отвечает медленно (минуты, а не секунды)** — значит отключён
  workflow **tg-live-poll** (частая причина: GitHub отключает
  расписания после 60 дней без коммитов — включите заново, он сам
  коммитит базу, так что это маловероятно). Включите tg-live-poll
  или запустите его вручную (Run workflow). Если poll.yml удалён —
  удалите строку `SKIP_TG_POLL: "1"` из monitor.yml, и команды станет
  забирать 30-минутный monitor (задержка до 30 мин).
- **Поиск городов**: «Москва» находит город «Москва — все аэропорты
  [MOW]» (он и нужен — метакод MOW покрывает Шереметьево, Домодедово,
  Внуково, Жуковский) плюс отдельные аэропорты списком. Совпадений
  всегда показывается до 5 лучших — тупика «слишком много совпадений»
  больше нет. Для городов-однофамильцев допишите страну через запятую:
  «Мельбурн, Австралия».

## Ограничения и честные оговорки

- **Цены кэшированные** (Aviasales): финальная цена подтверждается на
  кассе; алерт — «проверь срочно», не гарантия.
- **«История за 3 года»**: Data API не отдаёт истинных исторических
  цен. Вместо этого при создании трекинга делается **калибровка** —
  срез минимальных цен по датам месяца вылета (grouped_prices /
  month-matrix): бот предлагает разумную целевую цену (25-й перцентиль)
  и напоминает про типовую отсечку «за 6 недель до вылета» для пиковых
  направлений. По мере накопления собственной истории (≥ 10 дней
  наблюдений) дайджест сам предлагает перенести дату отсечки ближе,
  когда минимумы растут, или покупать раньше отсечки, когда лучшая
  цена уже на уровне минимума маршрута.
- **Бюджет нагрузки**: ~600 зап/мин на токен у Travelpayouts; конфиг
  по умолчанию держит ~5–8 зап/мин при 40 пользователях — запас ×100.
- Один бесплатный аккаунт GitHub/Travelpayouts — достаточно.

## Структура проекта

```
├── config.yaml              # глобальные настройки бота (маркер, валюта,
│                            # ручная кладь, лимиты нагрузки)
├── prices.db                # база (создаётся; коммитится workflow-ом)
├── data/
│   └── holidays.json        # производственный календарь РФ (обновляется)
├── IMPROVEMENT_PROMPT.md    # промпт ежемесячного самоулучшения
├── .github/workflows/
│   ├── monitor.yml          # cron-ы: мониторинг/30мин, дайджесты/час + коммит базы
│   ├── poll.yml             # tg-live-poll: непрерывный long polling (ответ 1–3 с)
│   └── holidays.yml         # производственный календарь: раз в ~90 дней
└── src/
    ├── main.py              # режимы monitor / bot / udigest / holidays
    ├── bot.py               # live-поллинг + команды + inline-кнопки + админ-панель
    ├── dialog.py            # визард 7 укрупнённых шагов (FSM в зашифрованном поле)
    ├── ui.py                # календарь (Пн первый, 🔴 выходные/праздники) и часы
    ├── holidays.py          # производственный календарь РФ + isdayoff-обновление
    ├── llm.py               # LLM-шутка к подтверждению (Z.ai GLM, ≤250 знаков, тихий фолбэк)
    ├── users.py             # регистрация, квоты, бан, waitlist, истечение
    ├── crypto.py            # Fernet-шифрование + HMAC-uid
    ├── monitor.py           # опрос трекингов пользователей (cadence/бюджет)
    ├── digest.py            # персональные дайджесты из базы
    ├── calib.py             # калибровка маршрута (советы по цене/отсечке)
    ├── places.py            # поиск городов/аэропортов (RU, опечатки)
    ├── config.py            # загрузка config.yaml
    ├── fetcher.py           # Travelpayouts API + deeplink
    ├── db.py                # SQLite: наблюдения, алерты, meta, users
    ├── rules.py             # окна времени, фильтры, правило min30
    ├── trends.py            # регрессия, вердикты «ждать/брать»
    ├── healthcheck.py       # пинг маячка живости
    └── notify.py            # отправка сообщений в Telegram (send_text)
```
