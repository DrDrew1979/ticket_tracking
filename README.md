# ✈️ altai-flight-monitor

Бесплатный мониторинг цен авиабилетов **Москва (MOW) ↔ Горно-Алтайск (OGK)**
на фиксированные даты июля 2027 с алертами в Telegram. Работает на GitHub
Actions по расписанию — сервер и включённый компьютер не нужны. Стоимость: 0 ₽.

## Что делает

1. **Каждые 30 минут** запрашивает цены из кэша поиска Aviasales
   (Travelpayouts Data API) по всем комбинациям дат:
   - туда: вылет из Москвы 16.07.2027 (после 20:00) — 18.07.2027 (до 23:59);
   - обратно: вылет из Горно-Алтайска 31.07.2027 (с 00:01) — 01.08.2027 (до 23:59);
   - время проверяется по **местному (аэропортовому)** времени.
2. **Главный алерт «min30»**: текущая цена ≤ минимума за последние 30 дней
   наблюдений **и** ≤ 45 000 ₽ за 1 человека (туда-обратно) → мгновенный пуш
   с deeplink на поиск Aviasales.
3. **Ежедневный дайджест в 09:00 МСК**:
   - лучшие текущие цены по всем парам дат;
   - вердикт тренда: «📉 падает — можно подождать ~3–7 дней» /
     «📈 вырос с минимума — брать сейчас» / «➖ стабильна»;
   - **дата отсечки** — до какого числа купить обязательно (статистика
     сезонных маршрутов: ~6 недель до вылета), со счётчиком дней.
4. Сохраняет историю цен в `prices.db` (SQLite), которая коммитится в репо —
   состояние переживает перезапуски, тренды считаются по реальным данным.

Агент **не покупает** билеты автоматически: покупка вручную по ссылке из
пуша (3-D Secure и правила площадок не позволяют иначе). Пуш приходит за
минуты после появления цены — обычно этого достаточно.

## Установка (15 минут)

1. **Создайте репозиторий** на GitHub (можно приватный) и загрузите эти файлы
   (`Add file → Upload files` или через git).
2. **Travelpayouts-токен**: зарегистрируйтесь на
   [travelpayouts.com](https://www.travelpayouts.com) (бесплатно), в кабинете
   возьмите API-токен.
3. **Telegram-бот**: создайте бота у [@BotFather](https://t.me/BotFather)
   (`/newbot`) → получите токен. Свой chat_id узнайте у
   [@userinfobot](https://t.me/userinfobot). Напишите боту первое сообщение
   `/start`, иначе он не сможет вам писать.
4. **Секреты**: в репозитории → Settings → Secrets and variables → Actions →
   `New repository secret`, добавьте три штуки:
   - `TP_TOKEN` — токен Travelpayouts;
   - `TG_TOKEN` — токен бота;
   - `TG_CHAT_ID` — ваш chat_id.
5. **Включите Actions**: вкладка Actions → «I understand…» (если попросит).
   Расписание стартует автоматически. Для проверки запустите вручную:
   Actions → flight-monitor → Run workflow → mode=`monitor`.
   В логе должно быть «Готово. Алертов за прогон: N».

Первые ~2 дня (`warmup_days` в config.yaml) ценовые алерты отключены —
бот копит базу, чтобы «минимум за 30 дней» имел смысл. Дайджест можно
запустить сразу: Run workflow → mode=`digest`.

## Настройка под себя

Всё меняется в `config.yaml`: даты/окна времени, целевая цена, лимит
пересадок (`max_transfers`), длительность (`max_duration_hours`), частота
опроса (в `.github/workflows/monitor.yml`, cron), партнёрский маркер.

## Ручная кладь (важное ограничение)

Кэшированный API не маркирует багажные тарифы. Минимальные тарифы российских
авиакомпаний на внутренних линиях, как правило, и есть безбагажные
(«только ручная кладь»), поэтому фильтрация по минимальной цене ≈ ваш запрос.
Для страховки deeplink в алерте содержит параметр фильтра ручной клади —
перед покупкой убедитесь, что тариф без багажа, на странице поиска.

## Ежемесячное самоулучшение (без Jules)

Google Jules недоступен из РФ, поэтому роль «агента-улучшателя» закрываем
одним из способов — раз в месяц, 20–40 минут:

1. **Проще всего — вернуться в чат с ассистентом Z.ai.** Скопируйте текст
   из `IMPROVEMENT_PROMPT.md` и отправьте в чат (приложив, если возможно,
   выгрузку истории цен). Получите обновлённые файлы → замените их в репо.
2. **Qwen Code CLI на своём компьютере** (бесплатно, ~2000 запросов/день,
   доступен из РФ): `npm i -g @qwen-code/qwen-code`, затем в папке проекта
   `qwen` и вставьте промпт из `IMPROVEMENT_PROMPT.md`. Агент сам изучит
   `prices.db` и внесёт правки — останется закоммитить и запушить.
3. **Aider + бесплатные модели OpenRouter** (`pip install aider-chat`,
   `aider --model openrouter/<бесплатная-модель>`) — аналогично п.2.
4. VPN + Jules обычно тоже срабатывает, но есть привязка к региону
   аккаунта Google — серая зона, не полагайтесь на это как на основной путь.

Это опциональный режим: базовые пороги уже настроены в `config.yaml`,
и бот без всяких улучшений будет корректно работать весь срок мониторинга.

## Ограничения и честные оговорки

- **Цены кэшированные**: финальная цена подтверждается на кассе; алерт
  означает «проверь срочно», а не «гарантированно доступно за эту цену».
- **Дата отсечки — эвристика** (пик июля на Алтай, типовая динамика продаж),
  а не гарантия; бот уточняет её по фактическому тренду.
- **Лимиты API**: ~288 запросов/день при опросе раз в 30 минут — с запасом
  в рамках бесплатных лимитов Travelpayouts. Если появится ответ 429 —
  увеличьте интервал cron.
- Один бесплатный аккаунт GitHub/Travelpayouts/Google — достаточно.

## Структура проекта

```
├── config.yaml              # все параметры задачи
├── prices.db                # история цен (создаётся автоматически)
├── IMPROVEMENT_PROMPT.md    # промпт для ежемесячного самоулучшения
├── .github/workflows/monitor.yml   # cron + коммит базы
└── src/
    ├── main.py              # точка входа (monitor / digest)
    ├── config.py            # загрузка конфига, пары дат
    ├── fetcher.py           # клиент Travelpayouts + deeplink
    ├── db.py                # SQLite: наблюдения и алерты
    ├── rules.py             # фильтры + правило «min за 30 дней ≤ 45000»
    ├── trends.py            # регрессия, вердикты «ждать/брать»
    ├── cutoff.py            # дата отсечки
    └── notify.py            # Telegram: пуш и дайджест
```
