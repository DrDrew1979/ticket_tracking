# Промпт для ежемесячного самоулучшения бота

Jules в РФ недоступен, поэтому роль «агента-улучшателя» можно исполнять
любым из способов (см. README, раздел «Ежемесячное самоулучшение»).
Текст ниже универсальный: подойдёт для Qwen Code / Aider / любого LLM
или просто вставьте его в чат ассистенту вместе с описанием проблемы.

---

Ты — аналитик и разработчик многопользовательского Telegram-бота
мониторинга авиабилетов (каждый пользователь задаёт свой маршрут,
даты и целевую цену командой /watch). Бот собирает цены по расписанию
в `prices.db` (SQLite: таблицы `observations` и `alerts`), алерты и
персональные дайджесты шлёт в Telegram.

Задача на этот месяц:

1. Проанализируй `prices.db`:
   - динамику дневных минимумов по каждой паре дат за весь период;
   - сколько алертов `min30` сработало, были ли ложные (цена после алерта
     упала ещё сильнее);
   - насколько фактическая динамика соответствует эвристике отсечки
     «за 6 недель до вылета» (src/digest.py) и порогам советов по
     накопленным данным (_cutoff_hint/_rising_pct).
2. Предложи и внеси в код улучшения, например:
   - уточнение порога тренда в `src/trends.py` (окна регрессии, пороги
     «падает/растёт») на основе реальных данных;
   - корректировку эвристик советов по отсечке в `src/digest.py`,
     если тренд это оправдывает;
   - регулировку частоты опроса (в `.github/workflows/monitor.yml`):
     учащать при цене близко к цели, редкие опросы в глубине сезона;
   - фильтр «шумных» алертов (когда «минимум за 30 дней» побит на копейки).
3. Не ломай формат БД: если нужна миграция схемы — сделай её
   обратно совместимой и опиши изменения.
4. Все пользовательские тексты (алерты, дайджест) — на русском.
5. Обнови README, если изменилось поведение. Перечисли изменения
   с обоснованием по данным из п.1.

Не запускай внешний трафик из тестов: используй fixture-данные.
